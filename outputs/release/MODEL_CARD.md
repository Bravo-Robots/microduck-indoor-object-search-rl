# MicroDuck Room Search supervisor — v0.2.1

**Purpose:** choose exploration and approach actions for three colour-coded
objects in the bundled simulation room. Simulation research model; physical
hardware deployment has not been validated.

The v0.2.1 packaging update keeps the v0.2.0 trained weights unchanged.

## Training and provenance

PPO with GAE, two 128-unit tanh layers, a categorical actor and scalar critic.
Training uses 256 GPU-vectorized planar SE(2) environments. The initial heading
curriculum decays during training. Objects and spawn sites are distinct.
The actor is partially observed; reward and terminal evaluation may use simulator
state, but hidden goal coordinates never enter actor observations.

[manifest.json](manifest.json) identifies the selected checkpoint, total
transitions, seed, interface and SHA-256 hashes. [RESULTS.json](RESULTS.json)
links the frozen release to the measured proxy and full-body suite outcomes.

## Interface

| Input indices | Meaning |
|---|---|
| 0–11 | 12 forward ranges divided by 2.5 m; 90° horizontal field |
| 12–14 | Visible flag, bearing/π, detected range/3 m |
| 15–17 | Last-seen flag, remembered bearing/π, remembered range/3 m |
| 18–33 | Two rings of eight odometry-based visit counts, clipped/scaled |
| 34–37 | x/2.5 m, y/2 m, sin(yaw), cos(yaw) |
| 38–43 | Previous executed action, one-hot |
| 44 | Elapsed supervisor steps / 180 |

The ONNX takes float32 `[1,45]` and returns six logits `[1,6]`. Choose argmax for
reproducible evaluation. Its observation scaling and action masks match the
PyTorch model; equivalence is tested.

| Action | Proxy command |
|---|---|
| 0 | Forward 0.20 m/s |
| 1 / 2 | Turn left / right at 0.9 rad/s |
| 3 / 4 | Forward 0.12 m/s while turning ±0.65 rad/s |
| 5 | Stop and confirm a visible, nearby goal |

The physical executor calibrates these to bundled motor policies and applies a
shared depth-only guard at 10 Hz. The guard may replace unsafe forward motion
with a turn. This is reported separately in each physical episode.

## Use and limits

```bash
bash run.sh rehearse --checkpoint outputs/release/best.pt --goal 0 --no-video
```

`search_policy.onnx` is not loadable as a `robotctl` motor policy. The robot's
motor interface is 61 inputs and 14 outputs; the supervisor has a different role.
Training did not use complete rigid-body dynamics. Full-body execution uses
ideal odometry, ideal planar forward depth and a rendered RGB colour detector.
Segmentation and true target positions are evaluator-only inputs.

The training/evaluation layout family is fixed apart from jittered furniture,
spawn and object locations. Arbitrary rooms, arbitrary object categories,
real-camera robustness and hardware safety have not been established. Inspect
contacts, falls, false confirmations and timeouts alongside success rate.
The RGB thresholds were calibrated using observed full-body suite failures;
that suite is a regression benchmark rather than an untouched test set.

Model weights are generated by this project. Their use with bundled robot mesh
assets remains subject to the separate asset licence in
[THIRD_PARTY.md](../../THIRD_PARTY.md).
